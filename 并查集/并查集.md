# **并查集**

并查集是一种高效管理**集合关系**的数据结构，核心用于解决「动态连通性」问题 —— 即快速判断两个元素是否属于同一集合，以及将两个不同集合合并。它的优势是**合并（Union）和查询（Find）操作的时间复杂度近乎 O (1)**



### **核心问题：为什么需要并查集？**

在处理元素间的 “连通” 关系时（如判断两点是否连通、分组管理等），传统方法（如遍历判断）效率低下：

*   若用数组记录每个元素的集合编号，合并操作需要遍历所有元素修改编号
*   若用链表，查询操作需要遍历链表找根节点

并查集通过「**路径压缩**」和「**按秩合并**」两个优化，将合并和查询的效率提升到近乎 O (1)，完美解决动态连通性问题



### **关键优化**

并查集的高效依赖两个关键优化：

1.  **路径压缩**

    查询时将所有元素的父节点直接设置为根节点，后续查询时路径会大幅缩短。

    例如：原本路径是 `x → a → b → root`，压缩后变为 `x → root`、`a → root`、`b → root`，下次查询 x 或 a 时可直接找到根节点
2.  **按秩合并**

    合并时，让秩小的集合 “依附” 于秩大的集合，避免形成深度过大的树。

    例如：若集合 A 的深度为 2，集合 B 的深度为 3，合并后 A 的根节点指向 B 的根节点，整体深度仍为 3，若反过来，深度会变为 4



### **复杂度**

*   **Find/Union 操作**：经过路径压缩和按秩合并后，时间复杂度可视为 O (1)。
*   **初始化**：时间复杂度 O (n)，需初始化父节点和秩数组。



### **应用场景**

1.  **图的连通分量**：判断图中有多少个连通分量，或两点是否连通（如社交网络中的 “好友关系”）
2.  **最小生成树算法**：用于判断添加一条边是否会形成环
3.  **岛屿数量问题**：如 Leetcode 200. 岛屿数量，合并相邻陆地并统计集合数
4.  **动态连通性**：如网络连接维护（判断两台设备是否连通，或连接两台设备）
5.  **等价类划分**：如根据等价关系（如 “同余”）将元素分组
